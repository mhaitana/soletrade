# Native application UI implementation

## Delivered code

`apps/mobile` is an SDK 58 native Expo application alongside the existing web app. Root owns the workspace dependency install/lockfile; app dependencies are pinned to the SDK 58-compatible React 19.3 / RN 0.88 line. Native iOS/Android tabs, routed screens, light/dark warm-neutral/blue tokens, Dynamic Type-compatible text, labelled inputs, native buttons/pickers/toggles and grouped settings are implemented. `src/app` contains route entrypoints/layouts only.

- `src/lib/supabase.ts`: SecureStore chunk adapter (no business database client writes), persisted PKCE session client.
- `src/lib/session.tsx`: exported `useSession()` supplies `{session,userId,workspaceId,bootstrap,request,refreshBootstrap}` and readiness/error/sign-out. Password/email links, PKCE code, email token-hash/implicit compatibility callbacks, foreground refresh, onboarding/workspaces, cached bootstrap and account-bound request checks are connected. Private navigation remounts on user/workspace changes. Account closure clears private device state, cache/widgets and local auth; workspace unavailability clears active views/cache while original-bound drafts remain blocked.
- `src/lib/api.ts`: `createRequest`, `authenticatedFetch`, typed `ApiError`, UUID mutation headers, explicit retry keys and `If-Match`. Streams/binaries use `expo/fetch`; JSON uses contracts envelopes. Native business data always goes through the server.
- `src/lib/resources.ts`: `useResource`, workspace paths, SQLite reference caching, loading/error/empty/content and cached refresh failures. Explicit authorization rejections never fall back to cached results.
- `src/screens/auth.tsx`: login/signup/verification, workspace create/switch, invitation acceptance, explicit keep/discard sign-out cleanup.
- `src/screens/editor.tsx`: `EditorScreen`, `DocumentForm`, `documentBody`, reference selection and reviewed prefills. Customers; invoice/quote multiple line items, quantities, cents, inclusive/exclusive tax, dates, customer, notes, payment-method structures, terms and optional content sections; Books transaction/GST/category forms; Drive earnings/mileage/vehicle/expense/settings; invitations/roles/business settings. New offline-supported records use `createDraft → explicitSave → syncOutbox` with one stable operation ID. Edits/lifecycle/billing remain online. Failed persistence retains form values; loaded forms hydrate once rather than overwriting typing during refresh.
- `src/screens/resources.tsx`: paginated/searchable/status-filtered resource lists, record details, customer timeline, invoice send/paid/void and quote send/conversion, PDF sharing, file opening/deletion, team roles, invitation resend/revoke and notification read actions. Source-linked Books records cannot be edited here.
- `src/components/trends.tsx` / `src/lib/periods.ts`: accessible real-series monthly/weekly/category/platform trends, quarter GST and financial-year-aware period controls. List filters send date/status/type/category/platform/customer/vehicle/unread parameters to server pagination.
- `src/components/payment-methods.tsx`: reusable invoice and workspace-default bank/PayPal/PayID instructions including optional labels/bank/reference. `src/components/date-field.tsx`: native SwiftUI/Compose calendar selection alongside editable dates.
- `src/screens/profile.tsx`: retained full-name editor against `/me/profile`, read-only email, and hAI reviewed profile prefills.
- `src/components/receipt-review.tsx`: existing OCR queue review, correction, apply/reject and original-receipt read; no duplicate expense without explicit action.
- `src/screens/tabs.tsx`: Home period/metrics/attention and quick actions; Sales, Money, Drive and native More menus; billing readout and native purchase navigation. Home refreshes the opt-in widget snapshot.
- `src/screens/tools.tsx`: cross-module search and native navigation, PDF/CSV Books reports, GST/BAS lodgement records, ownership request/acceptance, explicit owned-workspace closure selections and recent-auth account deletion flow. Reauthentication is a pushed screen so the underlying closure selection remains mounted.
- `src/screens/assistant.tsx`: persistent conversation list/details/rename/delete/write opt-in, incremental AI SDK SSE text/tool results and safe native navigation/form-prefill handoffs. Mutations still require user-reviewed normal Save or a confirmed assistant write flow. A durable turn UUID remains stable through failed sends; accepted turns clear the composer, and `ASSISTANT_TURN_ACCEPTED` reloads history without executing the message again.
- `src/screens/upload.tsx`: native document selection, retained durable file, signed upload/complete with stable per-stage operation IDs and retry.
- `src/screens/shell.tsx`: auth/bootstrap gate, AppLock, notifications, workspace reset, module gating and device feature routes to the separately implemented `ReceiptCaptureScreen`, `ShiftScreen`, `DraftsScreen`, `DeviceSettingsScreen`, `StorePurchaseScreen`. Session mounts `useNativeRuntime` and registers the background location task at module scope. Shell mounts the binding-aware `useAppShortcuts` hook; closed-account cleanup purges native state, private routes, SecureStore preferences, shortcuts and widgets.
- `app.config.ts`, `eas.json`, `.env.example`, assets, TypeScript/Babel/ESLint/Jest configuration and README provide local/dev-build setup. Widgets and Android quick-action plugin are registered. EAS/store signing accounts and production universal-link domains are deliberately deployment configuration.

## Remaining release verification

The app provides working customer-facing routes backed by real adapters; public release still requires configured-server end-to-end parity review against every existing web workflow, not a screen-count claim. In particular: production invitation/universal-link association, emailed OTP/PKCE delivery, real AI tool navigation/stream interruption, final provider-managed billing screens, real signed storage/PDF/email flows, accessibility/tablet visual review, store sandbox purchase/restore/refund and physical background/push/widget checks have not been exercised here. Native profile/default-payment editors, accessible trend series and server-filtered collection controls are implemented; final live data and native layout parity still needs device acceptance. The API report records the atomic edit-version checks that resolved the earlier optimistic-concurrency race. Maestro currently covers the main online journeys; offline/revocation/purchase/capture scenarios need device integration coverage in addition to the automated policy/outbox tests owned by the device worker.

The independent review corrections and RED/GREEN evidence are documented in `docs/mobile/ui-review-fixes.md`.
