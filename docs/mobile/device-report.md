# Native device implementation and validation

Implemented 25 October 2026. Native development builds are required. Automated checks below do not establish physical-device, store-sandbox or release readiness.

## Implemented behavior

- `src/offline/store.ts`: SQLite drafts, outbox and reference cache; original account/workspace binding; durable receipt originals in account/workspace-specific app-document folders with a pre-copy metadata journal; an explicit Save queues a new record. Drafts survive process death. Every record and upload/completion/OCR stage has a stable UUID operation. Concurrent replay is coalesced, interrupted requests reuse the original operation, transient errors back off, and authentication/module/permission failures retain blocked work. Existing-record edits and attachments require an online request. Signed upload URLs refresh against the original pending file; already-completed uploads skip bytes. Account closure purges personal local state and prevents late outbox/cache callbacks from restoring it. Complete unindexed originals recover into device-only `receipt-recovered` drafts with empty financial bodies, preserving original filename/MIME/size and stage IDs. Recovery verifies size/SHA-256, skips existing draft/upload references and never queues a save. Partial/unreadable copies remain inside their owning folder for discard/purge; financial fields are never guessed. Confirmed standalone uploads retire their recovery journals before clearing or replacing upload state; local originals are deleted only when no draft depends on them. Lost completion responses retain originals/journals until the server confirms that same bound file is complete. Independent durable upload files and unindexed copies are deleted on closure/discard, and discarded upload-operation callbacks cannot recreate their state. A definitively rejected structured validation error permits typed-form correction with a new operation UUID while preserving the original capture. Uncertain, sending, pending or previously potentially committed requests cannot be cloned.
- `src/native/shift.ts`: module-scope TaskManager registration using stable `expo-location`; user Start/Pause/Resume/Stop, manual fallback, durable session/points, per-account/workspace recovery and a single global recorder. Platform and selected workspace vehicle are retained. Inaccurate samples, implausible movement, pauses and missing-sample gaps never bridge distance. The user reviews/corrects total distance and supplies business purpose before one mileage operation is queued. No business-purpose inference or app-usage detection is enabled. Optional gig-app links come only from `EXPO_PUBLIC_GIG_APP_LINKS_JSON` (default `{}`), with provider-owned links verified by the operator per OS. Recording persists before launch; failed launch leaves the shift running and provides manual app-switching guidance. No built-in provider scheme is advertised as verified and no coordinates/status are appended.
- Private route upload defaults off and requires server preferences. Upload requires an already-synced reviewed trip and links to its actual server ID. Deletion removes local points immediately, retains an offline tombstone, replays deletion on reconnect and consumes other devices’ deletion tombstones before any route upload. Paginated server route history downloads to a recorder-bound local archive without creating or resuming a recording. Local and synced routes offer a read-only polyline map with start/finish markers, separate lines at gaps and a textual distance/gap fallback when Android Maps is unconfigured. Deleting an active route ends recording for review. Workspace mileage contains summary data; precise points use recorder-only `/me/routes`.
- `src/native/screens.tsx`: camera, image library and document/PDF capture; separate new-expense and existing-transaction attachment flows; existing transactions are selected by description/date/amount. Captures resume from Drafts. Review retains the original draft/extraction currency, defaults new entries to the bound workspace currency when available, validates against the shared supported-currency catalog and never converts extracted amounts. OCR is an explicit online request; asynchronous extraction is polled and reviewed before Apply. New-expense Save and OCR Apply are mutually exclusive for the capture.
- `src/native/device.tsx` and `runtime.ts`: explicit physical-device push registration, token/timezone refresh for registered devices, registration cleanup, selected categories, device-local quiet hours, guarded notification deep links, optional biometric lock, haptics, sharing and a signed-PDF sharing helper. Push does not determine business state. Foreground activation and a 30-second timer retry only already-saved outbox operations. Real recording/permission interruptions increment durable counters; intentional Pause/Resume/Stop do not. The bound operational-health observer receives those counters after recovery/sync without blocking sync and excludes route points, receipt bodies, gig-platform and vehicle details.
- `src/native/overview-widget.*.tsx`: isolated, synchronous Expo Widgets renderers. App code supplies workspace-bound last-synced snapshots; privacy settings and sign-out clear business data. iOS links open receipt capture or shift review/start in the app. Android’s Expo overview remains display-only.
- `plugins/with-android-quick-widget.js`: a separate Android **Soletrade quick actions** widget generates a real `AppWidgetProvider`, RemoteViews layout/resources and manifest receiver. Immutable explicit `PendingIntent.getActivity` actions start `MainActivity` at receipt capture, Start Shift or new invoice even with no JavaScript process. The widget contains no account/workspace data. All actions enter the app’s normal authentication/workspace/module gates.
- `src/native/shortcuts.ts`: real app-icon shortcuts for Start Shift, Capture Receipt and New Invoice through `expo-quick-actions`. The listener uses fixed internal targets, original account/workspace checks and current module checks; it ignores arbitrary incoming hrefs. Unauthenticated/unavailable workspaces clear dynamic shortcuts.
- `src/native/store-purchase.tsx`: actual Expo IAP catalog fetch and localized store prices, native subscription purchase, store restore/sync, original account/workspace intent binding, real Apple signed transaction/Google token verification and native transaction finishing only after successful server verification. Purchase eligibility is rechecked before charging. Google uses the actual base-plan offer token; Apple account token and Google hashed account/profile identifiers bind purchases. Before a native payment sheet, a server reservation is created with a durably stored operation UUID and its intent ID is persisted. Another attempt’s returned reservation ID never opens a second sheet. A launched uncertain/pending purchase is restored instead of relaunched; only exact provider-confirmed UserCancelled for a locally launched reservation requests cancellation. Unknown failures retain the reservation indefinitely. Verification includes the reservation ID when available; original-binding restores remain supported without local state. Google changes pass the current server-verified purchase token and product-level replacement parameters: upgrades/mixed sets immediately, pure subset downgrades at renewal, and same-product interval changes without proration. The preview distinguishes timing, and deferred modules are not reported active until confirmed by server entitlements. Native store renewal/cancellation management is available. Missing products, credentials or verification produce errors, never local entitlements.

## App integration

The UI owns package/app configuration and calls the exported feature screens with `MobileFeatureProps`. Register the location module before background launch. Call `useNativeRuntime` with the authenticated binding; wrap authenticated content with `AppLock`. Pause recording before sign-out, apply the selected keep/discard disposition, unregister push, and clear widgets. Account closure must suspend recording before `purgeClosedAccountData` removes the session rows. Closed-account purging deliberately bypasses pending-sync retention guards. Workspace revocation clears that workspace’s reference cache and retains its blocked drafts.

For Android route maps, configure the optional `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY` and the `react-native-maps` plugin’s `androidGoogleMapsApiKey`, restricted to the app package/signing certificate. iOS uses Apple Maps without Google credentials. Map preview never requests the device’s current location.

Keep the existing `expo-widgets` plugin with `enableAndroid: true`, `SoletradeOverview`, both platform `initialLayout` paths and an iOS app group. Also register `./plugins/with-android-quick-widget` in `app.config.ts`; it derives the configured Android package and app scheme. Current targets are `soletrade://feature/shift`, `soletrade://feature/receipt` and `soletrade://edit/invoices/new`. Rebuild native binaries after changing plugins. Widgets open a screen; recording and financial actions still require user review/confirmation.

The iPhone Shortcuts guide uses **Open URLs → `soletrade://feature/shift`**. It opens the screen for the user to choose a vehicle and start recording. App-icon shortcuts are registered dynamically for enabled modules. Register the `expo-quick-actions` plugin and call `useAppShortcuts` from the app shell; ordinary sign-out, account closure and workspace revocation call `clearAppShortcuts`. Automatic Android gig-app detection remains off.

Capture filesystem audit: SDK58 `File.copy`, `File.move`, `File.write` and digest APIs return promises and are awaited. The journal write resolves before copy; copy/hash/move finish before a durable file is returned. `File.create/delete` and `Directory.create/delete` are synchronous in the installed declarations, so purge completes those deletions before returning. Binary export sharing now also awaits `File.write` before handing off the URI. Recovery intentionally does not attribute legacy unindexed flat-folder files to an account; new captures always carry explicit folder/journal ownership, and indexed legacy files remain covered by draft/upload cleanup.
